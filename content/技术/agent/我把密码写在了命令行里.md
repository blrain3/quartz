杭州那台服务器的磁盘到了 80%，还剩 7.7GB。

不是我算好的。装过几个 Docker 镜像，跑过几个现在想不起来用途的容器，每次 `df -h` 看到那个数字，都想"下次再清"。它就是这么一点一点涨上来的，像抽屉里没人扔的说明书。

真正让我停住的不是"该删什么"。是 `ps aux` 里那个占着 20.9% 内存的 `python main.py`。我盯着这行字看了很久，认不出它。

一台自己的机器上跑着一件自己不认识的东西，那种感觉不是危险，是陌生。你不知道它在你家里做什么。

我停止了猜。Tailscale 连上去，把密码交出去，让它自己看。

### 它先做的不是删除

它跑的第一条命令不是 `rm`。

先是 `ps aux --sort=-%mem | head -15`，`df -h`，`cat /etc/os-release`。它得先把这台机器变成一个自己看得懂的对象，才敢动手。这个顺序在三分钟后有了回报：它从我认不出的那堆进程里，点出三样我确实不知道该怎么办的东西——那个 345MB 的 `python main.py`，一整套宝塔面板（BT-Panel、BT-Task、1panel-agent、1panel-core），还有两个跑过就忘的容器，ai-gateway 和 astrbot。

然后它问我删不删。

我说删干净。剩下的它自己判断：哪些能直接杀，哪些要先停服务，哪些得连 Docker 的镜像层和卷一起回收。最后是 12.21GB。磁盘从 80% 掉到 24%。

值钱的不是这 12GB。是"先侦察再动手"这个顺序。手起刀落和先看一眼再落刀，割下来的东西可能一样多，但只有后者留下了复核的余地——如果它上来就删，我事后没有任何办法判断它删得对不对。它先建立的那份理解，同时也是留给我的那份材料。

### 密码写在命令行里

这是我这次最不该做的事。

我用的是一条 `sshpass -p ... ssh root@...`。密码写在命令行里，进了 shell history，也在那几秒里进了进程列表。

Shell history 是个不会遗忘的文件。它不分轻重，你敲过的每一行都按顺序躺着，包括这一行。我后来把它清了，但"清掉痕迹"和"从没留下过痕迹"是两件事——这个区别我在别的地方教过别人，轮到自己的时候，我选了省事。

那我为什么还给了？因为不给就做不完。那台机器只有一个 1.6GB 内存的壳子，和一堆我认不全的进程。要我先修好密钥认证、配好 sudo 白名单，再让它动手，我大概会在第二步就搁置。

Agent 的价值恰好落在这道缝里：那些我知道该做、但一直没有做的事。

但这是权衡，不是方案。权限和能力的矛盾在 Agent 身上会被放大——它越有用，你要给的权限就越多；给得越多，一次判断失误的代价就越大。人犯错是单点的，Agent 犯错是批量的：你花一晚上才敢下的一条命令，它几秒钟就跑完了。

我现在只有两条缓解：Tailscale 把 SSH 来源限制在 tailnet 内，操作日志全落在 `~/.hermes/logs/` 可以回查。这两条都只是把事故半径缩小，没有把它变成零。

### 我给了一句空话

装完之后我说："去 GitHub 上找些项目学习"。

这句话是空的。没指定方向，没指定数量，没说学完要干什么。它自己把整个搜索空间补了出来——找仓库、读 README、判断哪些值得深读——最后挑了三个和第二大脑相关的：claude-obsidian，把笔记库变成知识图谱的技能；mnemosyne，五层认知架构的记忆系统；diarum，内置 RAG 的日更日记。

它 clone 下来，派子代理并行分析，把提取出的模式写进自己的记忆。

这里得说清楚，否则很容易滑成"它产生了意图"。真实发生的是一次含糊的目标函数加一次自主执行：我给的约束太松，它就必须自己发明判据。它挑的三个仓库确实切题——但"第二大脑"这个方向上本来就有足够多的高质量项目，随机命中的胜率并不低。

切题不等于懂我。

含糊指令的代价是结果不可预期，好处是成本可预期。这两样我都能接受，所以我暂时不打算把目标函数写细。

### 三层记忆，但都是文件

它有三层记忆。

最短的一层在会话里，一次对话结束就没了。中间一层是 `~/.hermes/memories/` 下的两份 Markdown——MEMORY.md 记我的偏好、环境和约定，USER.md 记我是谁、怎么写东西、在做什么项目。每次新会话醒来，它先读这两份，才知道在跟谁说话、该用什么语气。最长的一层是 `~/.hermes/skills/`，每一个重复出现的流程被写成一份 SKILL.md。

最后那层怎么长出来的，值得单独说一句。做过一次的事，第二次它知道怎么做；做过十次的事，不用我说它也会做。这不是记性好，是把重复劳动封成了肌肉记忆。

但三层有个共同点：都是文件。文件是静态的，等着被读取。真正让这套东西在用起来之后发生变化的，是它自己抓到的模式——今天那套第二大脑设计范式就是。那不是我写给它的，是它读完自己编码进去的。

我也得承认"让 Agent 活起来"是个文学说法，不是技术判断。从外面看，发生的只是一次检索命中加一次写入；它读着像"活"，是因为写进去的东西刚好落在下一次对话会用到的位置上。

### 一次问答和一套工作流

问一句、得一个答案、关掉——大多数人用 Agent 就是这样。这个用法能用，但它和一套能自己转下去的工作流之间，隔着一件东西：有没有持续输入。

它会用 RSS 订阅 GitHub Trending、技术博客和 newsletter。读完不是复制一段摘要，而是提取设计模式、跟已有的知识对齐、再决定要不要编码成可复用的东西。等到我下次聊到笔记方法，它把今天学的范式调出来——这时候我才知道它真学进去了，而不是读的时候朝空气点了个头。

自我改进那一环最慢。一次手动操作、两次重复，第三次才值得写成技能；写完还得等它在对的场景被触发，否则那只是一份没人读的文档，和写进笔记里然后忘掉没有区别。

### 它问我要不要试试

回头看，我对这件事的判断被自己的处境带偏过。

我让它接管服务器，是因为我懒得学正确做法；我夸它"自学"，是因为我给了一句空话而它没跑偏。这两件都不算它能力的证明，只算我松手的证明。

但有一件事，我没法用"我在偷懒"解释掉。

收尾之后它问我：要不要试试在服务器上跑一条 Hermes 命令。

不是"要不要我帮你跑"。是"你要不要试试"。

我拒绝了，那台机器只有 1.6GB 内存，跑一个 Agent 已经很紧。可这个问法本身说明，它已经在自己那里放下了三样东西：它在哪、它能做什么、哪些动作得我来按。前两样是能力。

第三样是边界。而边界感不是靠能力涨出来的——再涨一个量级，也不会自动长出"这件事该问你"。

所以问题已经不是"Agent 能不能管我的服务器"。它管过了，管得比我好。

问题是我为什么还站在旁边看。

我一开始以为是因为不放心。后来发现不是——我不放心的是密码那件事，不是它。它删的每一刀我都能回查，它学的每一样东西我都能读。

真正让我没走开的，是它最后那句话。所有的工具都不会回头问你。它们只在你按错键的时候报错，而报错也是给你看的。它问的那句不是报错。

密码是我给的，判断是我让出去的。它把最后这一件还回来了——一件不需要我按对键才存在的事。

它问我，因为它不知道。而这个"不知道"，是我在那台机器上唯一还不可替代的部分。
