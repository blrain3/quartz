这个站点的目录全是中文：`技术/`、`随笔/`、`读书/`、`诗歌/`、`影评/`。

理由很简单——它和我的笔记仓库是同一套结构。我每天在 Obsidian 里写的就是这些词，如果为了 URL 好看再维护一份英文别名，等于给自己加一道永远要同步的工序。**中文路径不是审美选择，是拒绝重复劳动。**

代价是，我要为此打三个补丁。

### 中文路径会被百分号编码

`技术/网站` 在浏览器地址栏里是 `%E6%8A%80%E6%9C%AF/%E7%BD%91%E7%AB%99`。而很多前端代码取当前页面标识时，直接读 `window.location.pathname`——拿到的就是那串编码后的东西。如果你的内容索引里存的 slug 是解码后的中文（大概率是），那么两者永远匹配不上。

表现出来是：**能看到、能点开，但功能悄悄失效**，比如关系图谱里点一个节点没反应。

```js
// 插件里的原样（压缩后）
function we(){let u=window.location.pathname

// 补丁之后
function we(){let u=decodeURIComponent(window.location.pathname)
```

这是 `scripts/patch-graph.mjs` 干的事。它改的是 `node_modules/@quartz-community/graph` 里压缩过的产物，所以只能锚定 `function we(){...}` 这种**压缩后的变量名**。这很脆——插件一升级，esbuild 换个名字，补丁就失配了。所以我在脚本里写死了版本号检查，并且**失配时直接 `exit 1` 让构建挂掉**。

为什么选择"挂掉"而不是"跳过"？因为这类补丁的失效是**静默**的：补丁不生效，站点照样构建成功、照样能访问，只是中文路径下的功能不灵了。如果它只打个 warning，我可能几个月后才发现。**宁可构建失败，也不要一个"看起来正常"的坏站点。**

### 但三个补丁里，只有一个真是 URL 问题

写这篇的时候我把三个脚本翻出来重新看了一遍，发现自己之前也想当然了：

| 脚本 | 真正的作用 |
|---|---|
| `patch-graph.mjs` | 中文 URL 解码（`decodeURIComponent`） |
| `patch-search.mjs` | **中文本地化**——把硬编码的 `"No results."` 换成 `"没有结果。"` |
| `patch-folder-tags.mjs` | 消除死链（下面细说） |

第二个跟 URL 一点关系都没有：搜索插件的"没有结果"文案是写死在英文里的，中文站点上就会蹦出一句英文。三个补丁，三种原因，但**根源是同一个**——插件没有把"最后一公里"做成配置项，用的人就只能去动它的产物。

### 40 条死链是怎么冒出来的

站点走极简风格，我决定把标签彻底去掉。标签一共在四个地方渲染，前三处都有配置项：`tag-list` 组件、`note-properties` 的 `includedProperties`、`tag-page` 索引页。第四处没有——**`folder-page`（文件夹列表页）**，它会把每个条目的标签硬编码渲染成链接：

```js
const tags = page.frontmatter?.tags ?? []
// ...
`<a class="internal tag-link" href="tags/${tag}">`
```

没有任何选项能关掉它。而我已经把 `tag-page` 禁了，于是文件夹页上每一个标签都变成了指向 404 的链接。**最要命的是它不报错**：构建成功，页面正常渲染，标签看起来还能点，我如果不特意去查，可能就一直挂在那里。所以我又写了 `scripts/patch-folder-tags.mjs`，把这行改成 `const tags = []`，让标签列表渲染成空。

### 方法：别用眼睛查

这个坑让我意识到一件事：**改了目录结构或插件配置之后，靠眼睛看是不够的**，得让机器去查。

我写了个脚本扫构建产物：遍历 `public/**/*.html`，抓出所有 `<a href>`（跳过外链、`#`、`mailto:`），对每个相对链接检查 `public/<路径>`、`<路径>/index.html`、`<路径>.html` 三者是否有任一存在。第一次跑，198 条内部链接里报出 **40 条死链**，全部集中在文件夹列表页；修完再跑，0 条。

如果是靠手动点页面，我大概要很久以后、甚至永远不会发现。这类问题的性质是：**它只在你恰好点到那一个链接时才会暴露。**

### 打补丁的代价

改 `node_modules` 有个绕不开的后果：**每次 `npm install` 都会把补丁冲掉**，所以它们必须挂在 `prebuild` 上，每次构建前重打一遍。

还有件事得诚实说：我现在维护着**两个给"当前根本没启用"的图谱插件的补丁**。因为我把关系图谱关掉了（极简风格不需要），所以 `patch-graph.mjs` 改的代码压根不会被打进产物，`patch-graph-output.mjs` 每次构建都只输出一句"没找到模式"的警告。留着它们是因为哪天想把图谱开回来——但这就是自建站的隐性成本：**你以为在维护站点，其实在维护一堆针对第三方产物打的补丁。**

### 值不值

我没有换英文路径。理由是这三个补丁加起来不到两百行，写完基本不用再管；而维护一套和笔记仓库平行的英文命名，是每天都要付的成本。

但我也确实因此想清楚了一条判断标准——**当配置项不存在时，打补丁是可以接受的；当配置项存在时，就不要打补丁。** 前者是工具没做好，后者是你没读文档。这两个工程上的账，还是分开算比较清楚。
