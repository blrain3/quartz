这个站点是给中文读者看的，所以我一直想把字体从 Google 搬到自己域名下——`fonts.googleapis.com` 在国内经常要转上十几秒，甚至直接超时，读者的首屏就一直挂着兜底字体。Quartz 恰好提供了看起来正好的配置：`fontOrigin` 保持 `googleFonts`，把 `cdnCaching` 关掉，文档的意思是"不缓存到 Google CDN，改成本地"，听上去就是自托管。

我照做了，构建也成功了。然后我顺手看了一下产物——**21MB**。

### 它下回来的其实是 TTF

问题出在构建时的那次请求：

```js
const cssResponse = await fetch(href)   // href 指向 fonts.googleapis.com
```

这个 `fetch` 跑在 Node 里，**不带浏览器的 User-Agent**。而 Google Fonts 的 CSS2 接口是靠 UA 判断对面能力的，它不知道请求方是什么，就返回最保守的版本——单体 TTF，没有 `unicode-range` 分片。于是 `Noto Sans SC` 变成了两个 10.5MB 的文件，加一起 21MB；更糟的是没有分片，读者进来第一件事就是把整个 21MB 拖下来。

这里有个容易被忽略的点：**"下载到本地"和"自托管"不是一回事**。前者是动作，后者要求下载到的东西本身就是给浏览器用的格式。

### 换成带 UA 请求，数字完全不一样

我用现代浏览器的 UA 重新请求了一次，同一个接口返回的东西判若两物：

| | 不带 UA | 带浏览器 UA |
|---|---|---|
| `@font-face` 数量 | 6 | **216** |
| 格式 | TTF | **woff2** |
| `unicode-range` | 无 | **216 条全有** |
| 文件数 | 6 | **113** |
| 总体积 | 21 MB | **4.47 MB** |

分片的意义在于，浏览器只下载当前页面实际用到的部分。我拿最长的中文文章测了一下：583 个不同字符，命中 `Noto Sans SC` 的 20 个分片，单页实际下载约 **1.1MB**，而且这些分片全站共享，加上缓存，老读者第二次访问基本是零成本。1.1MB 听起来还是不轻，但那是中文字体的固有成本，跟 21MB 不是一个量级的问题。

### 还有第二个坑：插件也在偷偷插一条

我一开始没发现，直到在产物 HTML 里搜了一遍 Google 域名——**有两条** Google Fonts 链接。第二条来自 `@quartz-community/quartz-fonts` 插件：它默认也工作在 `googleFonts` 模式下会注入自己的链接，而且用的是**它自己的默认字体**（`Source Sans Pro`），跟 `theme.typography` 里写的 `Noto Sans SC` 根本不是一套。也就是说，即使我自托管成功，读者还是会去请求 Google，而且请求回来一套用不上的字体。这个插件在这里没有存在的必要，直接 `enabled: false`。

### 最后是怎么做的

写了个 `scripts/fetch-fonts.mjs`，流程很短：带现代浏览器 UA 请求 Google Fonts 的 CSS2；校验拿到的确实是 woff2（防止哪天 UA 失效又退化回 TTF）；把 113 个 `fonts.gstatic.com` 链接改写成 `/static/fonts/...` 并下载落盘；最后把整份 `@font-face` 写在 `quartz/styles/_fonts.scss`，由 `custom.scss` 用 `@use "fonts"` 引入。

配置侧改成 `fontOrigin: local`（意思是"字体我自己管，你别插手"），并禁用那个插件。字体放在 `quartz/static/fonts/`，Quartz 的 static emitter 会自动把它复制到输出目录的 `/static/` 下，不需要额外接线。

### 一个 CI 上的坑

生成的 `_fonts.scss` 有 219KB，是机器产物，过不了 prettier 的格式检查。而我这个站点的 Cloudflare 工作流里跑着 `npm run check`（`tsc --noEmit && npx prettier . --check`），prettier 一失败，**整个部署就挂了**——第一次推送我就是这么翻车的，构建明明是好的。

修法是把 `quartz/styles/_fonts.scss` 加进 `.prettierignore`，生成的机器文件本来也不该逐行格式化。顺带一个经验：GitHub Pages 那条工作流**不跑** `npm run check`，只有 Cloudflare 那条跑，所以两边结果可能不一致，很容易误判成"部署没问题"。

### 结果

线上 `blrain.codes` 和 GitHub Pages 镜像里，`fonts.googleapis.com` 和 `fonts.gstatic.com` 的出现次数都是 **0**，字体文件返回 `HTTP 200` 且 `content-type: font/woff2`。

不过光把字体搬过来还不算完——它们得真的被缓存住，才算把这件事做完。
