> **时间复杂度分析统计的不是算法运行时间，而是算法运行时间随着数据量变大时的增长趋势。**

实际运行时间受硬件、编程语言、编译器等因素影响，不好衡量。时间复杂度关注的是**数据规模 $n$ 增大时，操作数量的增长趋势**——这才是算法优劣的核心。

---

## 大 O 记号

大 $O$ 记号（Big $O$ Notation）表示算法**时间复杂度的渐近上界（asymptotic upper bound）**，即"最坏情况下算法大概有多快"。

$$T(n) = O(f(n))$$

含义：当 $n$ 足够大时，$T(n)$ 的增长速度不会超过 $f(n)$ 的常数倍。

### 推算方法

1. **找出基本操作**：循环体中最核心的操作
2. **计算执行次数**：将循环嵌套展开为求和公式
3. **保留最高阶**：忽略常数和低阶项

> 例如 $T(n) = 3 + 2n$ → $O(n)$
> 例如 $T(n) = n^2 + 2n + 1$ → $O(n^2)$

## 常见时间复杂度

| 复杂度 | 名称 | 说明 | 示例 |
|:-----|:----|:----|:----|
| $O(1)$ | 常数阶 | 不随 $n$ 变化 | 数组随机访问、哈希表查找 |
| $O(\log n)$ | 对数阶 | 每次减少一半规模 | 二分查找、平衡二叉树查找 |
| $O(n)$ | 线性阶 | 与 $n$ 成正比 | 数组遍历、找最大值 |
| $O(n \log n)$ | 线性对数阶 | 分治策略的常见结果 | 归并排序、快速排序（平均） |
| $O(n^2)$ | 平方阶 | 双层循环 | 冒泡排序、选择排序 |
| $O(2^n)$ | 指数阶 | 每增加一个元素，工作量翻倍 | 纯递归斐波那契 |
| $O(n!)$ | 阶乘阶 | 全排列 | 旅行商问题（暴力） |

### $O(1)$ 常数阶
```java
int a = 1;
int b = a + 1;   // 不管 n 多大，都只执行这几次
```
操作次数与 $n$ 无关，恒定。

### $O(\log n)$ 对数阶
```java
int i = 1;
while (i < n) {
    i = i * 2;   // 每轮翻倍，执行 log₂n 次
}
```
典型场景：每次将规模减半（二分查找、平衡树、快速幂）。

### $O(n)$ 线性阶
```java
for (int i = 0; i < n; i++) {
    System.out.println(i);   // 执行 n 次
}
```

### $O(n \log n)$ 线性对数阶
```java
for (int i = 0; i < n; i++) {
    int j = 1;
    while (j < n) {
        j = j * 2;          // 外层 n 次 × 内层 log n 次
    }
}
```
典型场景：归并排序、快速排序、堆排序。

### $O(n^2)$ 平方阶
```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + j);  // n × n 次
    }
}
```

### $O(2^n)$ 指数阶
```java
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);  // 每次递归分裂为两个分支
}
```
n 每增加 1，工作量翻倍。大 n 时**不可接受**。

## 常见复杂度对比

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
```

| n | $O(1)$ | $O(\log n)$ | $O(n)$ | $O(n \log n)$ | $O(n^2)$ | $O(2^n)$ |
|:-:|:------:|:-----------:|:------:|:-------------:|:--------:|:--------:|
| 10 | 1 | ~3 | 10 | ~33 | 100 | 1024 |
| 100 | 1 | ~7 | 100 | ~664 | 10,000 | 不可行 |
| 1,000 | 1 | ~10 | 1,000 | ~9,966 | 1,000,000 | 不可行 |
| 10,000 | 1 | ~13 | 10,000 | ~132,877 | 100,000,000 | 不可行 |

## 最好、最坏、平均时间复杂度

| 类型 | 含义 | 使用场景 |
|:---|:----|:--------|
| **最好** | 输入最理想时的时间 | 偶尔参考，意义不大 |
| **最坏** | 输入最糟糕时的时间 | **最常用**，保证算法不会超过这个上限 |
| **平均** | 随机输入下的期望时间 | 能反映真实表现，但计算复杂 |
| **均摊** | 连续操作的平均时间 | 用于分析动态数组等结构 |

### 示例：冒泡排序

- 最好 $O(n)$：数组已经有序，优化版一轮扫描后提前退出
- 最坏 $O(n^2)$：数组完全逆序
- 平均 $O(n^2)$：随机输入

### 示例：快速排序

- 最好 $O(n \log n)$：每次分得均匀
- 最坏 $O(n^2)$：每次选到最大/最小值作为基准（可用随机基准优化）
- 平均 $O(n \log n)$：随机输入下的期望表现

## 时间复杂度分析口诀

> **先找 n，再找核心操作；数循环次数，写求和公式；最后化简，只保留最高阶。**
