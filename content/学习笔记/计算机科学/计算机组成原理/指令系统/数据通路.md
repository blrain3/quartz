## CPU 执行指令的本质：Fetch → Decode → Execute

数据通路控制着指令执行过程中数据的流动路径，关于指令的构成与编码方式，参见 [[计算机指令]]。

CPU 执行每条指令都在循环做三件事：

1. **Fetch（取指令）**：CPU 根据 PC（程序计数器）去内存读取指令，存入指令寄存器，PC 自动 +1
2. **Decode（译码）**：控制器解析二进制指令，识别操作码、寄存器编号、立即数、地址等信息
3. **Execute（执行）**：ALU（算术逻辑单元）真正执行计算，如加法、减法、逻辑运算、比较等

由此形成 CPU 的"生命循环"：

```c
while (true) {
    Fetch();    // 取指令
    Decode();   // 译码
    Execute();  // 执行
}
```

这就是所谓的 **指令周期（Instruction Cycle）**。

## 理解三个时间尺度

| 类型       | 定义               | 特点                    |
| -------- | ---------------- | --------------------- |
| **时钟周期** | CPU 时钟最基本的"滴答"节拍 | 最底层，如 3GHz 表示每秒 30 亿次 |
| **机器周期** | 完成一次基本操作所需时间     | 一次内存读/写，通常包含多个时钟周期    |
| **指令周期** | 完整执行一条指令的总时间     | 包含取指、译码、执行全过程         |


**层级关系：**

> 指令周期 > 机器周期 > 时钟周期

## 数据通路（Datapath）

> **数据在 CPU 内部流动的路径**

典型的路径包括：

- 寄存器 → ALU → 寄存器
- 内存 → 寄存器

数据通路由两类元件组成：

### 1. 操作元件（组合逻辑元件）
- **典型代表**：ALU
- **特点**：输入确定 → 输出立刻确定，无记忆能力
- **示例**：2 + 3 = 5

### 2. 存储元件（状态元件）
- **典型代表**：PC 寄存器、通用寄存器、状态寄存器
- **特点**：能够记住之前的数据，有记忆能力
