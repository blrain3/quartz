**UDP**（User Datagram Protocol，用户数据报协议）是另一种传输层[协议](https://developer.mozilla.org/zh-CN/docs/Glossary/Protocol)，和 TCP 处于同一层，但走的完全是另一条路子。它在互联网上用于**特别时间敏感**的传输，例如视频播放或 DNS 查询。

可以把 UDP 理解成**寄明信片**——扔进邮筒就不管了，不保证能送到，也不管送到了没有。UDP 的数据包被称为**数据报（datagram）**。

---

## UDP 如何工作

UDP 的工作方式极其简单：

1. 不需要提前建立连接（没有 TCP 的"三次握手"）
2. 不标注数据包的顺序
3. 不检查数据包是否到达
4. 直接向目标计算机发送数据报

换句话说：**一台计算机可以直接向另一台发送数据，无需事先征得许可**。

```text
TCP：    "要发数据了，在吗？" → "在" → "好的，开始发"
UDP：    "数据来了。"（直接扔）
```

UDP 协议运行在 IP 之上，数据传输过程如下：

1. 应用程序将数据以及目标信息提供给 UDP
2. UDP 附加头部（源端口、目标端口、长度、校验和）
3. UDP 数据报被传递给 IP 层进行寻址和路由
4. IP 协议添加自己的头部，将数据包转发到目标主机
5. 在接收端，UDP 移除其头部并将数据传递给目标应用程序

---

## UDP 头部结构

UDP 头部只有 **8 字节**，极其轻量：

| 字段 | 大小 | 描述 |
|---|---|---|
| **源端口** | 16 位 | 发送方的端口号 |
| **目的端口** | 16 位 | 接收方的端口号 |
| **长度** | 16 位 | UDP 头部 + 数据的总长度 |
| **校验和** | 16 位 | 错误检测（IPv4 可选，IPv6 强制） |

> 与 TCP 不同，UDP 的校验和是可选的。它不提供错误控制或流量控制，依靠 IP/ICMP 进行错误报告。

### UDP 伪头部

为了提高校验和的准确性，UDP 在校验和计算期间使用伪头部（仅用于计算，不随数据报传输）。它包含 IP 头部的部分内容（源 IP、目标 IP、协议号、UDP 长度），确保数据报被传递到正确的主机和端口。

## TCP 与 UDP 对比

UDP 比 TCP **更快**，但**可靠性更低**。

TCP 先通过"握手"建立连接，标记数据包的顺序，确认每个包是否到达——丢包就重传。UDP 不经过这些流程：

<p style="text-align: center;">
  <img src="https://www.cloudflare.com/img/learning/ddos/glossary/user-datagram-protocol-udp/tcp-vs-udp.svg" width="80%" />
</p>
<center><small>TCP vs UDP Communication</small></center>

| | TCP | UDP |
|---|---|---|
| 头部大小 | 20-60 字节 | 8 字节 |
| 连接 | 需要（三次握手） | 不需要 |
| 可靠性 | 保证送达，丢失重传 | 不保证，丢了就丢了 |
| 顺序 | 保证 | 不保证 |
| 速度 | 慢 | 快 |
| 校验和 | 必选 | 可选（IPv4） |
| 典型场景 | 网页、文件传输、邮件 | 直播、游戏、DNS |

> **技术细节：** 数据包丢失与其说是 UDP 的缺陷，不如说是互联网本身的工作方式决定的。大多数网络路由器在设计上不执行数据包排序和确认，因为那需要额外的内存，在大规模网络中不可行。TCP 是一种在应用需要时填补这个缺口的方法。

## UDP 的用途

UDP 常用于**对时间敏感、能容忍少量丢包**的场景——偶尔丢一帧比卡顿等待更好。

- **视频直播 / 音视频通话（VoIP）**：带有杂音的通话体验优于清晰但严重延迟的通话
- **在线游戏**：玩家位置需要实时更新，丢一两个包无所谓，但要够快
- **DNS 查询**：DNS 默认用 UDP，没收到回复就自己重试
- **DHCP**：设备获取 IP 地址时也用 UDP
- **RIP（路由信息协议）**：在路由器之间周期性发送路由更新
- **NTP（网络时间协议）**：以最小开销跨网络同步系统时钟

## UDP 与 DDoS 攻击

UDP 的无连接特性也带来了安全风险。攻击者可以不事先征得目标服务器的许可，直接向其发送大量 UDP 流量进行 **UDP 洪水攻击**。

**攻击过程：**

1. 攻击者向目标主机的随机端口发送大量伪造 IP 的 UDP 数据包
2. 目标检查端口上是否有活动应用程序（通常没有）
3. 目标回复大量 ICMP"目标不可达"消息，导致自身资源过载

**防御方法：**

- 监控异常的 UDP 流量峰值
- **速率限制**、**防火墙**和**入侵防御系统（IPS）**
- **分布式中间网络**：通过多个数据中心构成的网络接收并过滤流量
- 部署 **DDoS 防护服务**以应对大规模攻击

---

## 总结

- UDP **不建立连接**，**不保证可靠**，但**快**。
- 适合**实时性要求高、能容忍少量丢包**的场景。
- 8 字节的头部，比 TCP 轻量得多。
- 和 TCP 是传输层的两种选择——一个保稳，一个保快。
- 无连接特性也使其容易被用于 DDoS 攻击，需要额外的防护措施。
